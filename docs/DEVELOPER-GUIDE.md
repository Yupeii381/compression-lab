# Руководство по Compression Lab

Это карта программы и практическая инструкция по её изменению. Пути ниже указаны
от корня репозитория. Для разработки нужен .NET 10 SDK; пользователю готового
Windows-выпуска SDK не нужен. Начните с `CompressionLab.sln` в IDE.

## 1. Как проходит эксперимент

1. Браузер отправляет файл серверу. `FileService` сохраняет исходные байты и SHA-256.
2. Редактор формирует список цепочек: например, отдельно `gzip`, отдельно `lzma`,
   отдельно `rle → brotli`. Это независимые варианты для сравнения.
3. `ExperimentValidator` проверяет настройки и записывает версии и значения
   параметров каждого кодека. `JobQueue` создаёт задачу на каждую пару «файл / цепочка».
4. `LabWorker` берёт одну задачу и вызывает `ArchiveEngine`.
5. Ядро читает файл блоками. `CodecPipeline` вызывает `Encode` шагов по порядку,
   затем `Decode` в обратном порядке. `BlockBenchmark` проверяет совпадение байтов
   и измеряет время с учётом прогревов и повторов.
6. `ArchiveFormat` записывает контейнер `.clcs`. Задача получает результат,
   `LabRepository` сохраняет состояние, а браузер показывает таблицу и график.

Например, для `rle → huffman-example` сжатие идёт RLE, затем Хаффманом;
восстановление — сначала Хаффманом, затем RLE. Каждый блок независим:
словарь или таблицу частот нельзя рассчитывать на весь файл и молча хранить
в экземпляре кодека. При восстановлении экземпляр и процесс будут другими.

## 2. Карта проектов и модулей

### Общий контракт: `src/CompressionLab.Contracts`

| Файл / тип | Что делает |
|---|---|
| `ICompressionCodec.cs` / `ICompressionCodec` | Общие методы `Encode` и `Decode`, которые вызывает ядро |
| `CodecDescriptor` | ID, отображаемое имя, версия формата, описание и параметры метода |
| `CodecParameter` | Ключ, подпись, значение по умолчанию и границы числового параметра |
| `CompressionLab.Contracts.csproj` | Фиксирует идентичность сборки контракта для совместимости плагинов |

Этот проект связывает хост и кодек. Алгоритму не нужны ссылки на Web или Core.
Не меняйте сигнатуры интерфейса только в своей DLL: хост использует собственную
копию Contracts. Изменение самого контракта требует отдельного плана совместимости.

### Ядро: `src/CompressionLab.Core`

| Файл | Что делает |
|---|---|
| `CodecRegistry.cs` | Регистрирует методы, находит DLL, проверяет параметры и точные версии |
| `Plugins/PluginLoadContext.cs` | Загружает зависимости плагина из его папки, разделяет Contracts с хостом |
| `ArchiveEngine.cs` | Координирует сжатие/восстановление файлов, SHA-256, проверки и результаты |
| `Archives/CodecPipeline.cs` | Выполняет цепочку и проверяет размеры промежуточных блоков |
| `Archives/ArchiveFormat.cs` | Читает/пишет структуру `CLCS0001`, заголовок и блоки, проверяет границы |
| `Benchmarking/BlockBenchmark.cs` | Прогревы, повторы, время вызова алгоритмов и проверка восстановленных байтов |
| `BenchmarkSettings.cs` | Ограничения размера блока, повторов, прогревов и длины цепочки |
| `Models.cs` | `CodecStep`, `ArchiveHeader`, `BenchmarkResult`: данные ядра и контейнера |

Ядро не знает HTTP, браузера и пользовательской очереди. Если алгоритм можно
описать через `Encode`/`Decode`, добавлять условия `if (id == "мой-кодек")`
в ядро не требуется.

## 3. Как добавить собственный кодек

### Шаг 1. Создать библиотеку

Самый короткий путь — скопировать проект из `examples/CompressionLab.Codecs.Huffman`
и изменить алгоритм. Либо из корня репозитория:

```powershell
dotnet new classlib -n CompressionLab.Codecs.MyCodec -o src/CompressionLab.Codecs.MyCodec --framework net10.0
dotnet reference add src/CompressionLab.Contracts/CompressionLab.Contracts.csproj --project src/CompressionLab.Codecs.MyCodec/CompressionLab.Codecs.MyCodec.csproj
dotnet sln CompressionLab.sln add src/CompressionLab.Codecs.MyCodec/CompressionLab.Codecs.MyCodec.csproj
```

Добавление в решение удобно для IDE, но само по себе НЕ подключает DLL к приложению.
Имя сборки должно соответствовать `CompressionLab.Codecs.*.dll`.

### Шаг 2. Реализовать контракт

Класс должен быть публичным, не абстрактным, иметь публичный конструктор без
параметров и реализовывать `ICompressionCodec`. В `Descriptor` задайте:

| Поле | Пример | Правило |
|---|---|---|
| `Id` | `my-huffman` | Уникальный постоянный ID, сохраняется в архиве |
| `Name` | `Хаффман` | Отображается в интерфейсе |
| `Version` | `1` | Версия двоичного формата кодека, не версия выпуска программы |
| `Description` | `Статическое кодирование байтов` | Краткое описание для пользователя |
| `Parameters` | `[]` или список `CodecParameter` | Сейчас поддерживаются целые числа с границами |

Например, `[new("mode", "Режим", 1, 0, 2)]` автоматически создаст числовое поле.
Ключ `mode` поступит в `options["mode"]`; значения проверит реестр. Это только
пример объявления параметра: его влияние на алгоритм нужно реализовать самому.

`Encode` получает байты одного блока и возвращает самодостаточный закодированный
блок. `Decode` получает его и должен вернуть исходные байты. Таблицу частот,
дерево, словарь или свойства алгоритма включайте в результат `Encode`, если они
нужны для восстановления и не вычисляются из сохранённых параметров.

Обязательные условия реализации:

- Не хранить данные текущего блока в полях общего экземпляра. Очередь и запрос
  восстановления могут вызвать один кодек одновременно.
- Проверять `CancellationToken` перед работой и внутри долгих циклов.
- В `Decode` проверять длины и `maxOutputBytes` ДО выделения памяти или записи.
  Это верхняя граница, а не указание дополнить результат до данного размера.
- Отвергать повреждённые заголовки, усечённые данные и лишние байты.
- Не изменять полученный `input`; не полагаться на состояние предыдущего вызова.

### Шаг 3. Собрать и установить DLL

Для учебного примера из этого репозитория:

```powershell
dotnet build examples/CompressionLab.Codecs.Huffman -c Release
New-Item -ItemType Directory -Force plugins/Huffman
Copy-Item examples/CompressionLab.Codecs.Huffman/bin/Release/net10.0/CompressionLab.Codecs.Huffman.dll plugins/Huffman/
dotnet run --project src/CompressionLab.Web -c Release
```

Папка `plugins` здесь находится в корне решения. Web-проект копирует её содержимое
в выходную папку при сборке/публикации. Не копируйте учебную DLL туда, если она должна
остаться только демонстрацией: всё содержимое корневой `plugins` попадёт в выпуск.

Для готового приложения путь другой: создайте `plugins/Huffman` **рядом с EXE**
и скопируйте DLL туда. SDK получателю не нужен. Если библиотека имеет зависимости,
поставляйте их вместе с DLL в той же отдельной папке; для библиотек с зависимостями
удобно готовить комплект через `dotnet publish` проекта плагина. Для нативных
зависимостей нужна архитектура Windows x64 и корректная раскладка файлов.
Contracts у хоста общий: заменять его DLL пользовательской копией не следует.

После установки **полностью перезапустите приложение**, затем откройте «Методы
сжатия». Появится «Хаффман (учебный)», а в редакторе — новый вариант шага.
Отдельной регистрации в серверном коде и изменения JavaScript не требуется.
Загрузки на лету сейчас нет.

Если метод не появился, проверьте `diagnostics` в `GET /co-lab/api/state` и раздел
методов: правильный ли каталог, совпадает ли имя DLL с шаблоном, публичен ли класс,
есть ли конструктор и зависимости, уникален ли ID. DLL выполняется с правами хоста;
загрузка в отдельный контекст разделяет зависимости, но не изолирует недоверенный код.

### Шаг 4. Проверить корректность

Минимум: пустой блок, один байт, длинная серия одинаковых байтов, все значения
0–255, случайные данные, несколько блоков в `.clcs`, повреждения, ограничение
выхода и отмена. Проверьте `Decode(Encode(input)) == input` побайтно.
Рабочая проверка примера находится в `tests/CompressionLab.SelfTest/HuffmanTests.cs`.

```powershell
dotnet run --project tests/CompressionLab.SelfTest -c Release
```

Для исследования степени сжатия сравните независимые цепочки, например
`huffman-example`, `rle`, `gzip`, `lzma`, на одном файле и с одинаковыми настройками.
Результат может оказаться больше исходника: это нормальный результат эксперимента.

### Шаг 5. Сохранить совместимость архивов

Версия `Descriptor.Version` проверяется на точное совпадение с записанной в `.clcs`.
Если меняется формат байтов или значение параметров так, что прежние блоки нельзя
прочитать, выпустите новый ID либо сохраните прежнюю реализацию с её старым ID и
добавьте новую под другим. Простая замена `Version = "1"` на `"2"` приведёт к отказу
восстановления старых архивов этим кодеком. ID и версия — не оформление интерфейса.

## 4. Что показывает пример Хаффмана

`HuffmanCodec.cs` кодирует **байты 0–255**, поэтому работает с любым файлом.
Для текста UTF-8 это частоты байтов, а не букв Unicode. Кодирование именно букв
потребовало бы дополнительно определить текстовую кодировку и обратимо сохранить
способ представления; не преобразуйте произвольный двоичный файл в строку.

Порядок работы примера:

1. `Encode` подсчитывает частоты 256 значений в текущем блоке.
2. `BuildTree` объединяет два узла с наименьшей частотой. При равных частотах
   выбирается минимальный символ, чтобы восстановление построило такое же дерево.
3. `BuildCodes` назначает ветвям 0/1. Частые значения обычно получают короткие коды.
4. В начало записываются `HUF1` и 256 четырёхбайтовых частот в little endian:
   служебный заголовок занимает **1028 байт на блок**.
5. Коды упаковываются в байты от старшего бита к младшему; последний байт дополнен нулями.
6. `Decode` проверяет заголовок, сумму частот, предел выхода и длину битового потока,
   строит дерево и восстанавливает байты. Для единственного значения достаточно
   его частоты, поэтому битовый поток пустой; пустой блок также имеет только заголовок.

Это читаемый пример расширения. Он не оптимизирован для максимальной скорости или
минимального заголовка. На равномерных частотах размер почти не сокращается, а на
маленьких блоках таблица часто перевешивает выигрыш. Следующий эксперимент — компактное
хранение только ненулевых частот или канонические коды; такой формат оформляйте
как новый совместимый вариант по правилам выше.

| Желаемое изменение | Куда смотреть сначала | Что проверить |
|---|---|---|
| Добавить алгоритм | Новый проект и `ICompressionCodec` | Roundtrip, повреждения, DLL discovery, старые архивы |
| Добавить числовой параметр | `CodecDescriptor.Parameters` и реализация | Defaults, диапазон, сохранённые цепочки, версия формата |
| Добавить выпадающий список/строку параметров | Contracts, валидация и редактор | Это уже изменение контракта, нужна совместимость |
| Изменить интерфейс | `wwwroot` | Работа ссылок из `/co-lab/`, загрузка/восстановление |
| Добавить API | Endpoints + отдельный сервис | Валидация и проверка Origin, без дублирования логики ядра |
| Изменить расчёт метрик | `BlockBenchmark`, `BenchmarkResult`, `ExportService`, интерфейс | Смысл величин, единицы, JSON/CSV |
| Добавить приоритет задач | `JobQueue`, модели, Repository, API/редактор | Сохранение и перезапуск, отмена, выбор следующей задачи |
| Изменить хранение | `LabRepository`, `LabPaths` | Атомарность, блокировка, чтение прежнего состояния |
| Изменить контейнер | `ArchiveFormat`, `ArchiveHeader`, `CodecPipeline` | Чтение прежних `.clcs` и отдельная версия контейнера |
| Изменить адрес/запуск | `StartupOptions`, `LabApplication` | Автооткрытие, статические файлы, API и перезапуск обновления |
| Изменить распространение | Профиль, Publish-Release, workflow | Автономный EXE, ZIP, метаданные и интеграция обновления |

Практический порядок: сделайте копию данных, измените один модуль, выполните
`dotnet build CompressionLab.sln -c Release` и SelfTest, затем проверьте затронутый
сценарий в браузере на отдельном `--data-dir`. Для правок публикации выполните
release-smoke, для установщика — update-integration. HTTP-проверка создаёт файлы
и задачи: не запускайте её на своём основном рабочем пространстве.

## 6. Адрес `http://localhost/co-lab/`

По умолчанию приложение слушает локальный порт **80**, браузер открывается по адресу
`http://localhost/co-lab/`. Можно ввести адрес без завершающего слеша: сервер
перенаправит на `/co-lab/`, чтобы относительные ссылки работали правильно.
Корневой адрес `/` также перенаправляет туда. Файл hosts и покупка домена не нужны.

`localhost` — имя текущего компьютера, `/co-lab/` — путь приложения. Сетевой порт
остаётся, просто стандартный HTTP-порт 80 не пишется в адресе.
Справка: [устройство URL, MDN](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Web_mechanics/What_is_a_URL).
Префикс обрабатывается до маршрутизации через `UsePathBase`:
[порядок middleware, Microsoft](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/routing?view=aspnetcore-10.0).

Если порт 80 занят, остановите конфликтующий сервер, если он вам не нужен,
либо запустите `CompressionLab.Web.exe --port 8090`. Тогда адрес будет
`http://localhost:8090/co-lab/`. Приложение не перенастраивает и не выключает чужие службы.
Чтобы несколько программ делили один порт 80, потребуется отдельно настроенный
обратный прокси, например IIS; сам `/co-lab` не устраняет конфликт порта.

Приложение доступно на своём компьютере и работает пока запущен EXE. Это не
публикация сайта в интернете. Для доступа с других компьютеров потребуются
отдельные изменения сетевого режима, доступа и развёртывания.
