# Обновления через GitHub Releases

Источник настроен на репозиторий **Yupeii381/compression-lab**:

```text
https://github.com/Yupeii381/compression-lab/releases/latest/download/update-win-x64.json
```

Это постоянная ссылка на файл из последнего стабильного выпуска. GitHub направляет
её на актуальный релиз. Приложение не разбирает HTML страницы GitHub, а читает маленький
JSON: такой контракт проще проверять и поддерживать.
Официальная документация ссылок: https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases

## Как обновляется пользователь

1. Через пять секунд после запуска приложение проверяет последнюю версию.
   Проверку также можно запустить вручную во вкладке «Обновления».
2. Если версия новее, появляется описание и кнопка «Скачать и установить».
3. По нажатию приложение скачивает ZIP потоками и проверяет размер, SHA-256,
   платформу, описание выпуска и пути файлов внутри архива.
4. ZIP распаковывается во временную папку. Текущий эксперимент должен быть завершён
   или отменён; во время обновления новые задачи не запускаются.
5. Отдельный процесс из подготовленного выпуска ждёт закрытия старого хоста.
6. Старая папка переименовывается в резервную копию, новый выпуск устанавливается
   на прежнее место. Старые ярлыки и путь к EXE продолжают работать.
7. Пользовательские плагины копируются в новую папку, данные остаются отдельно.
   Новая версия запускается на прежнем порту с прежним каталогом данных.
8. Установщик проверяет, что запущен именно новый процесс нужной версии.
   Если запуск не удался, прежняя папка восстанавливается и старая версия запускается.

Автоматической установки без нажатия кнопки нет. Проверка не блокирует работу
сжатия при отсутствии интернета. Пользователь не устанавливает SDK и не запускает
BAT/PowerShell: весь механизм выполняется EXE приложения.

Версия 1.1.0 не содержит обновляющего кода. Её пользователям потребуется один раз
вручную установить выпуск 1.2.0 или новее (актуальный — 1.3.0). После этого дальнейшие версии можно получать
через интерфейс приложения.

## Первый выпуск на GitHub

1. Создайте публичный репозиторий `Yupeii381/compression-lab` и загрузите проект,
   включая каталог `.github/workflows`. Каталоги bin, obj, artifacts, data и .vs
   не нужны: они исключены через .gitignore.
2. Разрешите запуск GitHub Actions в репозитории, если он отключён.
3. Создайте и отправьте тег `v1.3.0`, привязанный к коммиту с этим кодом.

```powershell
git tag v1.3.0
git push origin v1.3.0
```

Workflow `.github/workflows/release.yml` установит SDK на машине GitHub, запустит
тесты, соберёт самостоятельный EXE, проверит скачивание/установку/откат на тестовом
выпуске и создаст GitHub Release с тремя вложениями:

- `CompressionLab-1.3.0-win-x64.zip` — программа вместе со средой выполнения;
- `CompressionLab-1.3.0-win-x64.zip.sha256` — контрольная сумма;
- `update-win-x64.json` — описание обновления для приложения.

На GitHub не передаются тестовые данные и тестовый будущий выпуск. Workflow использует
встроенный `GITHUB_TOKEN` с правом contents:write; дополнительный личный токен не нужен.
Если организация ограничивает права Actions, настройте разрешения репозитория.

Для следующего выпуска отправьте новый тег, например `v1.3.1`. Версия сборки и
описание обновления берутся из тега. Загрузка только исходников в main сама по себе
не предлагает пользователям обновление: нужен завершённый Release с вложениями.

В этой задаче GitHub-репозиторий и релизы не создавались; workflow подготовлен локально.
Пока Release с JSON не опубликован, проверка вернёт ошибку загрузки (например, 404),
а приложение продолжит работать.

## Ручная сборка выпуска

```powershell
./tools/Publish-Release.ps1 -Version 1.3.0 -Notes "Добавлено обновление через GitHub"
```

Скрипт готовит ZIP, SHA-256 и JSON в `artifacts/releases`. При ручном создании
GitHub Release приложите все три файла и используйте тег `v1.3.0`.
SHA-256 и размер считаются по окончательному ZIP: не изменяйте архив после генерации JSON.
Обычный «Source code.zip», автоматически предлагаемый GitHub, не подходит для установки.

Формат описания:

```json
{
  "format": 1,
  "version": "1.3.1",
  "runtime": "win-x64",
  "url": "https://github.com/Yupeii381/compression-lab/releases/download/v1.3.1/CompressionLab-1.3.1-win-x64.zip",
  "sha256": "64 шестнадцатеричных символа, вычисленных скриптом",
  "size": 50000000,
  "notes": "Описание изменений"
}
```

Пример иллюстрирует поля, а рабочий JSON генерируется скриптом с настоящими значениями.
Поддерживаются стабильные трёхкомпонентные версии; сравнение числовое (1.10.0 > 1.9.0).
Понижение версии и автоматическая установка prerelease не выполняются.

## Конфигурация и границы

Источник задаётся в `updates.json` рядом с EXE. `manifestUrl: null` отключает проверки;
`checkOnStartup: false` оставляет только ручную проверку. Аргумент `--update-feed`
позволяет разработчику временно заменить источник. Удалённые адреса должны использовать
HTTPS; HTTP разрешён только для тестового сервера на loopback.

SHA-256 проверяет соответствие ZIP описанию выпуска; это не отдельная цифровая подпись.
Доверие к источнику основано на HTTPS и контроле GitHub-репозитория издателем.
Пользовательский ZIP не выполняется до проверки контрольной суммы и распаковки.

Обновление требует права записи в папку установки и её родительский каталог.
Для обычной распакованной копии в пользовательской папке повышенные права не нужны.
Автоматическая установка из IDE не поддерживается: нужен самостоятельный выпуск
с release-info.json. Каталог данных должен находиться вне папки приложения.

release-info.json содержит список файлов издателя. При обновлении новые файлы издателя
заменяют прежние, а дополнительные файлы в plugins сохраняются. Контракт кодеков
имеет постоянную AssemblyVersion 1.0.0.0; менять его несовместимым образом нельзя
без отдельной миграции плагинов. На несовместимость пользовательского кодека влияет
сам код новой версии, а не механизм копирования.

Резервная копия остаётся рядом с приложением (`.backup-...`), подготовленные файлы
и результат установки — в `data/.updates`. Неудачная новая папка сохраняется как
`.failed-...`. Они оставлены для ручного восстановления и диагностики; после проверки
новой версии старые копии можно удалить. Автоматическая очистка и цифровая подпись
в этот выпуск не включены.

## Проверки

```powershell
dotnet run --project tests/CompressionLab.SelfTest -c Release
./tools/Publish-Release.ps1 -Version 1.3.0
./tools/Publish-Release.ps1 -Version 1.3.1 -OutputRoot artifacts/update-test-packages
./tests/update-integration.ps1
```

Проверки используют отдельные каталоги и локальные порты. Они проверяют неверную
контрольную сумму, ошибку новой версии с возвратом к прежней, успешную установку,
сохранение файлов/очереди и исполнение внешнего кодека после обновления.
Ничего не загружается в GitHub при локальном тестировании.
