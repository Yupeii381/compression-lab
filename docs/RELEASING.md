# Подготовка выпуска

## Для пользователей

Распространяется ZIP **CompressionLab-1.3.0-win-x64.zip**. Внутри EXE, среда .NET,
веб-интерфейс, плагины и описание лицензии LZMA SDK. Пользователь распаковывает
архив целиком и запускает EXE. SDK, Runtime, PowerShell и BAT-файлы для запуска
выпуска не нужны. Браузер открывается автоматически после запуска локального сервера.

Это папка самостоятельного приложения, а не один автономный EXE: переносить
только EXE нельзя. Такой выпуск сохраняет простое подключение DLL из plugins.
Публиковать можно весь ZIP как вложение релиза на выбранной площадке.
Загрузка в какой-либо внешний аккаунт в этой задаче не выполнялась.

Данные находятся в `%LOCALAPPDATA%\CompressionLab\data` и переживают замену папки
выпуска. Старую рабочую папку можно подключить аргументом `--data-dir`.
Программа поддерживает другой локальный порт: `--port 8090`.

## Для разработчика

На машине разработчика нужен .NET 10 SDK. Профиль `Windows-x64` доступен
в Visual Studio и в командной строке:

```powershell
dotnet build CompressionLab.sln -c Release
dotnet run --project tests/CompressionLab.SelfTest -c Release
./tools/Publish-Release.ps1 -Version 1.3.0
./tests/release-smoke.ps1
```

Перед повторной публикацией остановите EXE именно из целевой папки. Для работы
с уже запущенной версией используйте новую выходную папку через `-o` и передайте
её EXE тесту: `./tests/release-smoke.ps1 -Executable "полный путь к EXE"`.

Профиль включает SelfContained, win-x64 и отключает trimming/AOT, чтобы сохранять
динамическую загрузку сторонних кодеков и метаданные reflection.
Справка Microsoft: https://learn.microsoft.com/en-us/dotnet/core/deploying/

Сборка получает runtime через стандартный restore .NET. Среда входит в выпуск,
поэтому её обновление требует пересборки и распространения новой версии приложения.
Для другой архитектуры/ОС нужен отдельный профиль с соответствующим RID.

Для локальной разработки обновляйте Version в csproj и текст инструкции при
изменении возможностей. Скрипт публикации принимает номер выпуска отдельно,
а GitHub Actions получает его из тега и передаёт в сборку и описание обновления.
Контракт кодеков и версия контейнера меняются отдельно от версии приложения.
Выпуск 1.3.0 читает прежний формат CLCS0001; тестовый старый архив включён в Fixtures.

## Возможное дальнейшее развитие

Установщик и ярлык, подпись EXE и отдельный интерфейс
управления плагинами можно добавить следующим шагом. Для публикации как общего
веб-сервиса потребуется отдельная работа над сетевым режимом, авторизацией,
хранением и изоляцией выполнения кодеков: текущий выпуск предназначен для ПК пользователя.


## GitHub Releases и онлайн-обновления

Актуальный процесс подготовки ZIP и описания обновления:

```powershell
./tools/Publish-Release.ps1 -Version 1.3.0
```

Workflow `.github/workflows/release.yml` выполняет сборку, проверки и публикацию
выпуска при отправке тега v1.3.0 (или следующей версии). Версия берётся из тега.
Подробная инструкция для Yupeii381/compression-lab: [обновления](UPDATES.md).
