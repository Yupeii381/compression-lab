# Compression Lab — C#

Локальное приложение для исследования сжатия на **C# / .NET 10 / ASP.NET Core**.
Ориентир — соседний Python-проект CompressionLab. Интерфейс на русском языке,
работает в браузере без внешних сервисов, CDN и сборщика JavaScript.

## Запуск готового приложения

Выпуск **1.3.0 для Windows x64**: `artifacts/releases/CompressionLab-1.3.0-win-x64.zip`.
Распакуйте ZIP целиком и запустите `CompressionLab.Web.exe`. Браузер откроется
автоматически на **http://localhost/co-lab/**. Устанавливать .NET SDK или Runtime
и запускать скрипты не нужно: среда .NET включена в папку выпуска.

EXE нельзя переносить отдельно от DLL и папок выпуска. Остановка — Ctrl+C
или закрытие окна приложения. Данные хранятся отдельно в
`%LOCALAPPDATA%\CompressionLab\data`, поэтому замена папки выпуска не удаляет их.

Если порт занят: `CompressionLab.Web.exe --port 8090`. Другой каталог данных:
`CompressionLab.Web.exe --data-dir "D:\CompressionData"`. Для прежнего рабочего
пространства укажите старый каталог data; автоматического переноса данных нет.
Справка — `--help`; отключение открытия браузера — `--no-browser`.

Адрес без номера порта использует стандартный HTTP-порт 80. Если он занят другим
сервером, выберите другой порт: например, `--port 8090` откроет
`http://localhost:8090/co-lab/`. Приложение не перенастраивает другие службы.

Раздел «Обновления» проверяет GitHub Releases репозитория `Yupeii381/compression-lab`.
Новая версия скачивается и устанавливается по кнопке, с перезапуском, сохранением
данных и внешних кодеков, резервной копией и возвратом при ошибке запуска.
Для включения онлайн-проверки нужно опубликовать Release с описанием обновления.
[Настройка GitHub и выпуск обновлений](docs/UPDATES.md).

Прежняя сборка в `artifacts/app` оставлена отдельно; актуальный самостоятельный
выпуск находится в `artifacts/releases`.

## Запуск и сборка для разработчика

Нужен .NET 10 SDK. Откройте `CompressionLab.sln` в Visual Studio либо используйте:

```powershell
dotnet run --project src/CompressionLab.Web -c Release
dotnet publish src/CompressionLab.Web -p:PublishProfile=Windows-x64
```

Профиль публикации также доступен в Visual Studio. `start.bat` и `test.bat`
остаются удобными командами для разработки и не входят в пользовательский ZIP.
Проекты не используют сторонних NuGet-библиотек; для самостоятельной публикации
SDK получает стандартные пакеты runtime. Подробности: [подготовка выпуска](docs/RELEASING.md).

## Работа

1. Добавьте файлы или нажмите «Тестовый набор». Выберите файлы галочками.
2. Создайте независимые цепочки сравнения. Внутри цепочки добавляйте шаги,
   выбирайте кодеки и параметры; стрелка ↑ меняет порядок шагов.
3. Выберите блок 64 КиБ–4 МиБ, 1–10 повторов и 0–3 прогрева.
4. Запустите эксперимент. На каждый файл и цепочку создаётся отдельная задача.
5. Скачайте `.clcs` либо экспортируйте результаты в CSV / JSON.
6. Во вкладке «Файлы» можно восстановить скачанный `.clcs` без исходного файла.

Реализованы Gzip, Brotli, DEFLATE, RLE и LZMA1. RLE и LZMA загружаются как
**внешние DLL**: веб-проект не ссылается на их типы при компиляции.
Кодеки Gzip/Brotli/DEFLATE имеют отдельные классы и общий потоковый базовый класс.
Уровень 0–3 соответствует NoCompression/Fastest/Optimal/SmallestSize .NET,
а не числовым уровням одноимённых утилит.

RLE — простой формат пар «количество, байт», не PackBits. Он полезен как
понятный пример собственного кодека и может сильно увеличивать случайные данные.
LZMA1 — настоящая C#-реализация из официального LZMA SDK 26.04; исходники уже
включены в `src/CompressionLab.Codecs.Lzma/Vendor`.

## Архитектура

| Проект | Назначение |
|---|---|
| CompressionLab.Contracts | ICompressionCodec, описание метода и параметров; единственная обязательная зависимость плагина |
| CompressionLab.Core | Каталог и загрузка DLL, валидация параметров, контейнер, цепочки, замеры и восстановление |
| CompressionLab.Codecs.BuiltIn | Gzip, Brotli, DEFLATE через стандартную библиотеку .NET |
| CompressionLab.Codecs.Rle | Самостоятельный пример внешнего кодека |
| CompressionLab.Codecs.Lzma | Адаптер + исходники официального C# LZMA SDK |
| CompressionLab.Web | HTTP API, очередь, сохранение состояния, браузерный интерфейс |
| CompressionLab.SelfTest | Исполняемые проверки без дополнительных тестовых библиотек |

После рефакторинга HTTP-обработчики, сервисы, очередь, хранение и настройки разделены
в Web; формат архива, выполнение цепочки и замеры разделены в Core. Точка входа
содержит только запуск приложения. Карта модулей и рекомендации по изменениям:
[архитектура](docs/ARCHITECTURE.md).

**Подробное руководство:** [все модули, свои изменения и подключение Хаффмана](docs/DEVELOPER-GUIDE.md).
Рабочий пример кодирования по частотам байтов находится в
`examples/CompressionLab.Codecs.Huffman`. Он проверяется SelfTest и устанавливается
как внешний плагин по инструкции; в стандартные пять методов автоматически не входит.

Ядро не знает конкретные методы сжатия. Цепочка — список ID, версий и параметров.
Плагины загружаются в отдельные AssemblyLoadContext с единым экземпляром Contracts.
У каждого плагина может быть своя папка с управляемыми и нативными зависимостями.
Ошибка загрузки одной DLL отображается во вкладке методов и не отключает остальные.

## Добавление своего кодека

Можно встроить исходники алгоритма в отдельный Class Library проект или использовать
библиотеку как зависимость. Ни ядро, ни HTTP API, ни редактор цепочек менять не нужно.

1. Создайте проект .NET 10 с именем сборки **CompressionLab.Codecs.MyCodec**.
2. Добавьте ссылку на проект `CompressionLab.Contracts`.
3. Реализуйте публичный класс с конструктором без параметров:

```csharp
using CompressionLab.Contracts;

public sealed class MyCodec : ICompressionCodec
{
    public CodecDescriptor Descriptor => new(
        "my-codec", "Мой кодек", "1", "Описание алгоритма",
        [new("level", "Уровень", 3, 1, 9)]);

    public byte[] Encode(byte[] input, IReadOnlyDictionary<string, int> options,
        CancellationToken cancellationToken)
    {
        cancellationToken.ThrowIfCancellationRequested();
        // Здесь вызов вашей реализации сжатия.
        throw new NotImplementedException();
    }

    public byte[] Decode(byte[] input, IReadOnlyDictionary<string, int> options,
        int maxOutputBytes, CancellationToken cancellationToken)
    {
        // Ограничивайте размер ДО выделения памяти/записи результата.
        // Здесь вызов вашей реализации распаковки.
        throw new NotImplementedException();
    }
}
```

Полный рабочий пример — `src/CompressionLab.Codecs.Rle/RleCodec.cs`.
Для стороннего исходного алгоритма — `src/CompressionLab.Codecs.Lzma/LzmaCodec.cs`.

4. Соберите библиотеку и скопируйте DLL **вместе с её зависимостями**:

   - при запуске исходного проекта: в `plugins/MyCodec` **в корне решения**,
     затем снова запустите `start.bat`; сборка скопирует папку к приложению;
   - при запуске готовой сборки: в `plugins/MyCodec` рядом с EXE выпуска, затем
     перезапустите EXE.

5. Откройте «Методы сжатия»: кодек и его числовые параметры появятся автоматически.

Имя сканируемой DLL должно соответствовать `CompressionLab.Codecs.*.dll`.
ID кодека должен быть уникальным. Contracts нельзя изменять только на стороне плагина:
хост и плагины используют один контракт. Совместимые обновления могут сохранять
версию формата; несовместимое изменение encode/decode требует новой версии или ID.
При восстановлении проверяется точное совпадение версии кодека из архива.

Экземпляры кодеков должны быть без изменяемого общего состояния либо потокобезопасными:
очередь и запрос восстановления могут обращаться к одному кодеку одновременно.
Encode/Decode получают один блок. Декодер обязан ограничивать выход
`maxOutputBytes`; отмена кооперативная, через CancellationToken.
Служебные свойства, необходимые декодеру, должны быть включены в байты блока
или в параметры, которые сохраняет контейнер.

DLL выполняется в процессе хоста с правами приложения. AssemblyLoadContext разделяет
зависимости, но не является песочницей. Подключайте собственные/доверенные реализации.
Для нативного C/C++-алгоритма используйте адаптер P/Invoke и поставляйте библиотеку
для архитектуры хоста; сам интерфейс кодека остаётся тем же.

### Как подключён LZMA

В проект включены оригинальные ICoder.cs, CRC.cs и каталоги LZ, LZMA, RangeCoder.
Адаптер создаёт новый encoder/decoder на каждый вызов, задаёт словарь и fast bytes,
сохраняет пять байтов свойств SDK и исходную длину перед потоком LZMA1.
Память словаря ограничена 16 МиБ; выход проверяется ограниченным потоком.
Это пример подключения **исходников алгоритма**, без внешнего `7z.exe` и без подмены
LZMA другим методом. Ссылки на источник и лицензию — в `NOTICE.md` проекта кодека.

## Формат, метрики и данные

`.clcs` — собственный контейнер C#-версии, сигнатура `CLCS0001`.
JSON-заголовок хранит исходное имя, длину, SHA-256, размер блока и шаги с версиями
и параметрами. Для каждого блока записаны размеры всех промежуточных стадий и
итоговые данные. Декодирование идёт в обратном порядке. После последнего блока
проверяются полная длина, SHA-256 и отсутствие лишних байтов.

Каждый повтор при сжатии проверяется побайтным восстановлением блока;
итоговый восстановленный поток проверяется SHA-256. Это проверка корректности,
не цифровая подпись архива. Неудачные/отменённые операции удаляют частичные результаты;
существующий файл при CLI-восстановлении не перезаписывается.

```powershell
dotnet src/CompressionLab.Web/bin/Release/net10.0/CompressionLab.Web.dll --restore result.clcs restored.bin
```

Для готовой сборки: `CompressionLab.Web.exe --restore result.clcs restored.bin`.
Плагины для восстановления ищутся рядом с исполняемым приложением, в `plugins`.

Размер архива включает все служебные данные. Процент сокращения:
`(1 - archiveBytes / originalBytes) * 100`; для пустого файла процент не определён.
Время — медиана суммарного времени вызовов кодеков всех блоков за один повтор,
без файлового чтения/записи, прогрева и побайтного сравнения. Инициализация кодеков
включена. JSON сохраняет все повторы, параметры, версии кодеков и сведения о среде.
График сравнивает размеры цепочек для одного выбранного файла.

Очередь имеет одного исполнителя. Пауза не прерывает текущий эксперимент.
После штатной остановки незавершённая задача ставится обратно в очередь;
после аварийного выхода задачи running также перезапускаются с начала.
Каталог data по умолчанию — `%LOCALAPPDATA%\CompressionLab\data`.
В нём файлы, очередь, результаты и состояние паузы сохраняются в `state.json`;
оригиналы — `blobs`, архивы — `artifacts`. Запись состояния атомарная.
Блокировка host.lock защищает каталог от одновременного использования двумя хостами.
План редактора хранится в localStorage браузера. Для резервной копии остановите хост
и скопируйте каталог data. Свой каталог:

```powershell
dotnet run --project src/CompressionLab.Web -- --data-dir D:/CompressionData
```

Лимит загружаемого файла/архива — 256 МиБ, промежуточного блока — 32 МиБ,
цепочки — 8 шагов, очереди — 2000 активных задач. Исходник обрабатывается блоками.
В браузере скачивание восстановленного файла буферизуется средствами браузера.

## Проверка

```powershell
dotnet build CompressionLab.sln -c Release
dotnet run --project tests/CompressionLab.SelfTest -c Release
# При запущенном приложении (PowerShell 7):
./tests/http-smoke.ps1
# Самостоятельный EXE на отдельном порту, без зависимости от установленной среды:
./tests/release-smoke.ps1
```

SelfTest проверяет все 5 кодеков, загрузку плагинов, пустые, случайные и повторяющиеся
данные, многоблочные цепочки, ограничения, повреждения, отмену и защиту существующих
файлов. HTTP-тест добавляет свои данные в рабочее пространство: используйте тестовый
`--data-dir`. Он проверяет загрузку, очередь, валидацию, скачивание, восстановление,
экспорт и запрет запросов с постороннего браузерного origin.

## Отличия от Python-версии

Это самостоятельная рабочая C#-версия основных сценариев, не полная копия всех
возможностей оригинала. Пока отсутствуют LZ77/LZ78/LZW/Huffman, LZMA2, LZ4, LZFSE,
PPMd, Zstandard и Bzip2; их можно добавить отдельными плагинами.
Нет сетевого режима с ключами доступа, приоритетов, отложенного запуска,
жёстких процессных таймаутов, замеров RSS и параллельных воркеров.
Хост слушает только 127.0.0.1 (по умолчанию порт 80); защита Host/Origin включена.
Плагины работают в процессе, поэтому кодек, игнорирующий отмену, нельзя принудительно
прервать без остановки хоста. `.clab` и база SQLite исходной Python-версии
не импортируются: `.clcs` использует отдельный формат и каталог данных.
