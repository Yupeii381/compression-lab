# Compression Lab

Локальное веб-приложение для исследования методов сжатия. Сервер, исходные
файлы, очередь и результаты находятся на компьютере, где запущено приложение.
Участники подключаются через браузер к этому компьютеру.

## Быстрый запуск в Windows

1. Установи **Python 3.12 x64** с официального сайта Python. Оставь включённым
   Python Launcher (`py`).
2. Распакуй архив целиком и запусти **`start.bat`**. При первом запуске будут
   установлены зависимости; потребуется интернет. В дальнейшем приложение
   работает без интернет-сервисов.
3. Открой **http://localhost:8080**. Нажми **«Тестовый набор»** или загрузи свои
   файлы, выбери методы и нажми **«Запустить»**.

Окно терминала оставь открытым. `Ctrl+C` останавливает сервер. Если порт занят:

```powershell
.\start.bat --port 8090
```

## Быстрый запуск в Linux / macOS

Нужны Python 3.12 и модуль `venv`. В каталоге проекта:

```bash
chmod +x start.sh
./start.sh
```

Затем открой http://localhost:8080. Для ручной установки:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

В Windows ручной запуск:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

## Доступ участникам из сети

Останови локальный сервер и запусти **`start-network.bat`** в Windows либо:

```bash
./start.sh --network --port 8080
```

Сервер слушает `0.0.0.0`. Терминал покажет случайный ключ доступа. Он сохраняется
в `data/host-key.txt`; передай участникам ключ и адрес
**`http://IP_ТВОЕГО_ПК:8080`**. Адрес можно посмотреть на странице «Локальный хост»
или через `ipconfig` / `ip addr`. Разреши входящие подключения к выбранному порту
в брандмауэре для нужной сети. Участникам нужен только браузер.

Это **общее рабочее пространство**: все обладатели ключа видят общие файлы,
результаты и очередь и могут управлять задачами. Индивидуальных аккаунтов,
ролей, квот на каждого участника и изоляции проектов в этой версии нет.

Для удалённых участников можно подключить машины через VPN и использовать
VPN-адрес хоста. При доступе через интернет используй HTTPS. Для HTTPS-прокси
на том же компьютере запусти:

```bash
./start.sh --network --proxy-headers
```

Прокси должен передавать исходный `Host` и `X-Forwarded-Proto`. Перенаправленные
заголовки принимаются только от `127.0.0.1` / `::1`. Прокси направляет запросы
на `http://127.0.0.1:8080`. Прямой TLS тоже поддерживается:

```bash
./start.sh --network --ssl-certfile fullchain.pem --ssl-keyfile privkey.pem
```

Ключ можно задать через переменную окружения `CLAB_ACCESS_KEY` (не меньше 16
символов в сетевом режиме). Для смены автоматически созданного ключа останови
сервер, удали `data/host-key.txt` и запусти его снова. Сессия браузера действует
8 часов. Удалённая публикация и настройка маршрутизатора не выполняются автоматически.

## Поддерживаемые методы

| Метод | Реализация | Настройки |
|---|---|---|
| LZ77 | эталонная реализация Python | окно, глубина поиска |
| LZ78 | эталонная реализация Python | размер словаря |
| LZW | эталонная реализация Python, 16-битные коды | размер словаря |
| LZMA1 | liblzma, контейнер `.lzma` | уровень, словарь |
| LZMA2 | liblzma, контейнер XZ | уровень, словарь |
| LZ4 | liblz4, frame | уровень |
| LZFSE | оригинальная библиотека Apple | фиксированный режим библиотеки |
| PPMd | PPMd I.2 через pyppmd | порядок модели, память |
| Huffman | канонический побайтовый код, Python | фиксированное построение |
| RLE | PackBits, Python | минимальная длина серии |
| Zstandard | libzstd | уровень |
| Brotli | Google Brotli | качество, окно |
| Gzip | zlib DEFLATE + Gzip frame | уровень |
| DEFLATE | zlib, raw stream | уровень, окно |
| Bzip2 | libbzip2 | уровень |

**«PPMP» принято как PPMd**, и `ppmp` поддерживается как API-псевдоним.
Если подразумевался другой вариант PPM, его нужно определить отдельно.
Отсутствующая библиотека отображается недоступной; подмены другим методом нет.

Эталонные Python-кодеки имеют собственные форматы и подходят для исследования
содержимого и последовательностей преобразований. Их скорость нельзя считать
скоростью оптимизированных C/C++-реализаций того же алгоритма. LZ77 и LZ78
не заменены DEFLATE. Для производительных практических экспериментов используй
нативные кодеки.

## Планирование и сравнение

- Каждая **цепочка** — независимый вариант сравнения. Внутри неё шаги
  последовательно преобразуют данные: например, **RLE → Huffman → Zstandard**.
- Для каждого файла и каждой цепочки создаётся отдельная задача. Параметры
  задаются на каждом шаге; можно менять порядок шагов и порядок цепочек.
- Настраиваются число повторов, прогрев, блок 64 КиБ–4 МиБ, приоритет,
  отложенный запуск и лимит времени на задачу 10–1800 секунд.
- Очередь можно приостановить, поднять задачу по приоритету, отменить или
  повторить неудачную задачу. Приостановка не прерывает уже запущенные задачи.
- План цепочек сохраняется на сервере. Незавершённые задачи после перезапуска
  запускаются **заново**, а не с последнего обработанного блока.
- Доступно 1–4 параллельных процесса. Для корректного сравнения скорости
  выбирай **1**: параллельные задачи конкурируют за ресурсы компьютера.

Размер после сжатия — **полный размер `.clab`**, включая заголовок, таблицы и
кадры кодеков. В деталях отдельно показаны сжатые данные и служебные байты.
Сокращение рассчитывается как `(1 − размер архива / исходный размер) × 100%`.
Отрицательное значение означает увеличение. Для пустого файла процент не
определяется. На графиках сравниваются цепочки **одного выбранного файла**.

Время — медиана измерений вызовов кодеков, без чтения и записи файлов;
инициализация кодека для блока включена. Прогрев не входит в медиану.
Каждый блок полностью восстанавливается в обратном порядке, сравнивается
побайтно, а для всего файла проверяется SHA-256. Экспорт JSON сохраняет
параметры, измерения всех повторов, настройки блоков, версии библиотек и
сведения о системе. CSV подходит для анализа в таблицах.

**Кодеки перезапускаются на границах блоков.** Поэтому размер блока влияет на
сжатие и замер, а результат может отличаться от целого файла в `xz`, `7z` и
других программах. Цепочки не обязаны улучшать сжатие; это проверяется экспериментом.

## Файлы и результаты

По умолчанию всё находится в `data/` рядом с `run.py`:

- `blobs/` — неизменяемые оригиналы, адресованные по SHA-256. Одинаковые байты
  хранятся одной копией независимо от имени загрузки.
- `artifacts/` — результаты `.clab`; частичные результаты не выдаются.
- `lab.sqlite3` — метаданные, очередь, результаты, планы и настройки.
- `host-key.txt` — ключ сетевого режима.

Файлы читаются и загружаются потоками. Весь исходный файл не помещается в RAM.
Одна задача запускается в отдельном процессе. Размер промежуточного блока
ограничен 128 МиБ; на Unix есть лимит адресного пространства процесса 1,5 ГиБ.
В Windows доступны ограничения блока и времени, без Unix-ограничения памяти.
На Unix пиковый RSS показан для всего процесса, а не только памяти кодека;
в Windows эта метрика не измеряется.

Можно выбрать другой диск и лимиты:

```bash
./start.sh --data-dir /mnt/ssd/compression-data --max-upload-mib 2048 --storage-limit-gib 50
```

Лимит `storage-limit-gib` относится к сумме размеров **загруженных оригиналов**.
Архивы занимают дополнительное место. При загрузке проверяется свободное место.
Файлы, использованные в экспериментах, нельзя удалить через интерфейс, чтобы
сохранить воспроизводимость. Для резервной копии останови сервер и скопируй
весь каталог данных. Только один экземпляр хоста может использовать один каталог.

## Восстановление скачанного результата

`.clab` — контейнер приложения с описанием цепочки и независимыми блоками.
Это не ZIP / RAR: восстанови его командой, используя те же зависимости:

```bash
.venv/bin/python run.py --restore result.clab --output restored.bin
```

В Windows:

```powershell
.venv\Scripts\python.exe run.py --restore result.clab --output restored.bin
```

Исходное имя, размер, параметры цепочки и SHA-256 находятся в контейнере.
Существующий выходной файл не перезаписывается. Восстановление не зависит от
наличия исходника или базы задач. Обратная обработка внешних `.zip`, `.xz` и
других архивов через веб в этой версии не реализована.

## Устройство проекта

| Модуль | Ответственность |
|---|---|
| `app/codecs.py` | каталог методов, параметры и encode/decode |
| `app/storage.py` | потоковые файлы, адресация, SQLite и транзакции очереди |
| `app/scheduler.py` | выбор задач, отдельные процессы, таймауты, отмена |
| `app/worker.py` | цепочки, повторы, измерения, восстановление и SHA-256 |
| `app/archive.py` | чтение и запись переносимого контейнера CLAB |
| `app/server.py` | HTTP API, сессии, загрузка и скачивание |
| `app/host_lock.py` | защита каталога от двух хостов одновременно |
| `web/` | русскоязычный интерфейс без внешних CDN и сборки frontend |

Backend — **Python/FastAPI**, нативные методы — библиотеки C/C++. RabbitMQ
для одного локального хоста не требуется: очередь хранится в SQLite.
Существующее знание C# можно использовать для будущей замены HTTP/планировщика
на ASP.NET Core, сохранив контракт worker и формат измерений.

### Основные API

Токен для программного клиента: `Authorization: Bearer КЛЮЧ`.

| Запрос | Назначение |
|---|---|
| `POST /api/files?name=example.bin`, raw body | потоковая загрузка |
| `GET /api/files`, `GET /api/methods` | файлы и кодеки |
| `POST /api/experiments` | создание плана и задач |
| `GET /api/tasks`, `GET /api/experiments` | очередь и результаты |
| `POST /api/tasks/{id}/cancel`, `/retry`, `/promote` | управление задачей |
| `PATCH /api/settings` | `paused`, `workers` |
| `GET /api/tasks/{id}/download` | скачать CLAB |
| `GET /api/experiments/{id}/export?format=csv` | CSV; `format=json` для JSON |
| `POST /api/presets`, `GET /api/presets` | сохранённые планы |

Тело эксперимента:

```json
{
  "name": "RLE и Huffman",
  "file_ids": ["ID_ЗАГРУЖЕННОГО_ФАЙЛА"],
  "pipelines": [
    {"label": "Huffman", "steps": [{"method": "huffman", "params": {}}]},
    {"label": "RLE + Huffman", "steps": [
      {"method": "rle", "params": {"min_run": 3}},
      {"method": "huffman", "params": {}}
    ]}
  ],
  "repeats": 3,
  "warmups": 1,
  "block_kib": 1024,
  "priority": 0,
  "timeout_seconds": 300
}
```

## Проверки

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tests/integration_live.py
```

В проверенном Linux-окружении прошли 9 тестов: все 15 кодеков на тексте,
бинарных данных, сериях и пустом входе, сброс словарей, многоблочная цепочка,
CLAB и метрики, приоритет/время/отмена/перезапуск, дедупликация, HTTP-защита,
лимиты и экспорт. Интеграционная проверка запускает настоящий TCP-сервер,
загружает файл, выполняет 16 задач в отдельных процессах и восстанавливает
все скачанные архивы. Наличие Windows x64 wheels для Python 3.12 подтверждено;
запуск на Windows и визуальная проверка в браузере не проводились.

## Устранение проблем

- **Не найден `py` в Windows:** установи Python 3.12 с Python Launcher или
  используй путь к `python.exe` при ручном запуске.
- **Не создаётся venv в Linux:** установи пакет `python3-venv`, соответствующий
  установленному Python.
- **Метод недоступен:** переустанови зависимости в используемый venv. Кодек не
  заменяется другим методом.
- **Порт занят:** выбери другой `--port`; останови старое окно сервера.
- **Два хоста используют одни данные:** останови первый сервер или выбери другой
  `--data-dir`. Переключение local/network выполняется перезапуском одного хоста.
- **Участники не подключаются:** проверь IP, порт, локальную сеть/VPN и брандмауэр;
  режим `localhost` принимает подключения только с машины хоста.
- **Задача слишком долгая:** уменьши уровень/словарь/блок/повторы или увеличь
  таймаут. Ошибка одной задачи не останавливает оставшуюся очередь.
